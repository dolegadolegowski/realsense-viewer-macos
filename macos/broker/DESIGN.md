# realsense-usbd: RealSense USB broker for macOS - implementation spec (rev. 3)

Normative spec for the broker that lets the viewer run without an administrator password at every launch, including on
standard accounts. Read with `CONTRACT.md` (what the RSUSB `usb_*` abstraction must do; section 11 here corrects it)
and `rs-usb-broker-protocol.h` (the wire protocol; its comment block is part of this spec). MUST/SHOULD/MAY are
normative. Paths are relative to the repo root unless they start with `src/` (= `third_party/librealsense/src/`).

Fixed decisions (not revisited here): label/Mach service `io.github.dolegadolegowski.realsense-usbd`, legacy
LaunchDaemon, ad-hoc signing, cdhash allowlist + console-user/root peer policy + MDM `allowCamera`, VIDs 0x8086/0x38E5,
irreversible HWM opcodes denied and everything else librealsense does allowed, lease per client connection with
hand-back after the last lease plus grace, C++17 daemon with static libusb and no librealsense code, xpc_shmem data
path, broker chosen by a HELLO inside librealsense with the in-process libusb path as fallback, no new environment
variables.

## 2. Daemon

### 2.1 Process and modes
2.1.1 One binary, `realsense-usbd`, C++17, linked with `libusb-1.0.a` (static) and IOKit, CoreFoundation, Security,
SystemConfiguration only. libxpc/libdispatch come from libSystem.
2.1.2 `--daemon` (launchd): MUST refuse to run (fault log, `exit(0)` so KeepAlive does not loop) unless `geteuid()==0`,
`getppid()==1`, `proc_pidpath` is `/Library/PrivilegedHelperTools/io.github.dolegadolegowski.realsense-usbd` and the
config passes 5.3. It MUST `umask(077)`, `chdir("/")`, ignore its environment, run the libusb event thread and
completion paths at `QOS_CLASS_USER_INTERACTIVE`, and create the listener with
`xpc_connection_create_mach_service(RSUSB_SERVICE_NAME, q, XPC_CONNECTION_MACH_SERVICE_LISTENER)`.
2.1.3 `--probe` (any user, used by the launcher and the installer): connects as a client (PRIVILEGED flag), HELLO with
4.7.2's rules, prints one line (`ok <build>` or the reason), exits: 0 OK, 2 unreachable/rejected (incl. not
allowlisted: INVALID about 1 s after connecting), 3 AUTH_USER, 4 AUTH_CAMERA_DISABLED, 5 AUTH_VERSION, 6 AUTH_LIMIT.
Never touches USB, never reads the config.
2.1.4 `--dump` (any user; opens no device, libusb descriptor reads only): prints the ENUMERATE `devs` array, built by the
real snapshot code (2.4.2) incl. the device filter, as an XML plist with the fixture keys of 9.0.2 (`RegistryID`,
`DriversAttached`, `ActiveConfig` added, `tok` omitted). Used to capture fixtures.
2.1.5 `--handback-recorded` (root only, used by the uninstaller after `bootout`): runs the startup sweep (2.7.7)
synchronously, waits up to 10 s per device for drivers, prints one line per device, exits 0. The running daemon
holds `flock(LOCK_EX)` on `<state dir>/lock`; this mode takes it with `LOCK_NB` and refuses (exit 1) if it is held.
2.1.6 The mock backend, fake policy and test listener exist only in test binaries; the shipped binary has no test switch.

### 2.2 Queues, threads and handles
2.2.1 Main queue: listener, SIGTERM source, console-user and managed-preferences notifications, idle timer, watchdog
timer (1 Hz while any device call or CLOSE wait is running).
2.2.2 Per connection: one serial queue (the peer's target queue). It parses and validates every message and owns the
connection's tables (handles, requests, leases, counters, send counter). It MUST NOT block on device I/O or wait for
completions. `libusb_submit_transfer` and `libusb_cancel_transfer` of bulk/interrupt transfers are called on it
(non-blocking IOKit async calls; covered by the watchdog).
2.2.3 Per device: one serial device queue for anchor open/capture, messenger handle open/claim/release/close,
RESET_EP (`libusb_clear_halt`), hand-back and loss cleanup.
2.2.4 Handles (matches in-process libusb, where every `usb_messenger` has its own `libusb_device_handle`):
- anchor handle: opened by the first OPEN of a device instance, used only for `libusb_kernel_driver_active`,
  `libusb_detach_kernel_driver` and `libusb_get_configuration`; kept open (keeps darwin's `USBDeviceOpenSeize` held)
  until hand-back or loss.
- messenger handle: one `libusb_open` per messenger (darwin only increments `open_count`, no IOKit open), its claimed
  interfaces, all its transfers and `clear_halt`. Claim and release run on it only while it has no transfer in flight
  (OPEN before the reply, CLOSE after all completions), so no lock is needed between messengers: darwin keeps claimed
  interface state per handle, and control transfers use the device-level IOKit object.
- The rwlock of rev. 1 is removed.
2.2.5 One libusb event thread: `while (!stop) libusb_handle_events_completed(ctx, &stop);`, woken by
`libusb_interrupt_event_handler`. Transfer and hotplug callbacks run there; they MUST NOT block or call libusb sync
APIs; they only update state, send XPC messages (non-blocking) and `dispatch_async` follow-up work.
2.2.6 The daemon never calls libusb's synchronous transfer functions. CONTROL/BULK are async transfers answered from
their completion (2.6), so sync ops of one messenger run concurrently as in-process.

### 2.3 Backend
2.3.1 The core talks to `usb_backend` (abstract, `daemon/backend.h`): `list()` (snapshots, instance keys, registry
IDs, drivers-attached), `open_anchor/close_anchor`, `kernel_driver_active`, `capture` (= detach), `active_config`,
`open_handle/close_handle`, `claim/release`, `submit` (control/bulk/interrupt, completion callback), `cancel`,
`clear_halt`, `interfaces_held_elsewhere` (2.7.3), `hand_back(registry_id)`, `registry_id_of(device)`, hotplug
arrived/left notifications. Semantics are libusb's (BUSY on double submit, NOT_FOUND on cancel of an idle transfer,
whole-pipe abort on cancel, NO_DEVICE after loss, ACCESS for an interface open elsewhere).
2.3.2 libusb backend: one `libusb_context` for the daemon lifetime; hotplug registered with
`LIBUSB_HOTPLUG_ENUMERATE` and `LIBUSB_HOTPLUG_MATCH_ANY`, filtered by 2.4.1 in the callback. libusb log output goes
to os_log at debug level.
2.3.3 The backend MUST NOT keep a `libusb_device*` across a hand-back: the old instance is dropped on its hotplug LEFT
and the new one arrives with a new token.

### 2.4 Device registry and ENUMERATE
2.4.1 Device filter (applied before a device enters the registry):
- VID 0x38E5: any PID. VID 0x8086: only PIDs in `daemon/rs-usbd-pids.h`, generated by `scripts/gen-usbd-pids.sh`
  from every `const uint16_t <NAME>_PID = 0x<hex>;` in `src/ds/d400/d400-private.h` and `src/ds/d500/d500-private.h`
  (incl. recovery/DFU PIDs), sorted, deduped; the script fails if it finds fewer than 20.
- Refused regardless of PID: any interface of class 0x01 audio, 0x02 CDC, 0x08 mass storage, 0x09 hub, 0x0A CDC data,
  0xE0 wireless, or HID with subclass 1 and protocol 1 or 2 (boot keyboard/mouse). Logged once per instance.
2.4.2 Registry (mutex-protected): token -> device for every present allowed device. Tokens are nonzero 64-bit, never
reused within a daemon run. One `libusb_ref_device` per entry. Each entry also holds `state` in {listed, capturing,
handing_back, gone}, the lease set and the grace timer; LEASE, hand-back start and loss change them under this mutex.
2.4.3 Snapshot (built on arrival and on refresh until complete): `get_device_path` algorithm (bus,
`libusb_get_port_numbers` up to 8, address), `libusb_get_device_descriptor`, every configuration
`c < bNumConfigurations` via `libusb_get_config_descriptor`, interfaces in `config->interface[]` order, every
altsetting's 9 descriptor bytes from the parsed fields and its `extra` verbatim, altsetting 0's endpoints as 7-byte
records. If any configuration read fails the snapshot is incomplete: not cached, not listed, retried at the next
refresh. An interface exceeding a header limit is left out of the snapshot (logged); the device is still listed.
2.4.4 ENUMERATE copies cached complete snapshots of `listed` and `capturing` devices sorted by IORegistry entry ID ascending (the
order HW-2 must confirm against a fresh in-process `libusb_get_device_list` with two cameras) and does no device I/O.
Refresh from `libusb_get_device_list` on every hotplug event and at most once per ENUMERATE if older than 1 s.

### 2.5 Per-device state, LEASE, OPEN and CLOSE
2.5.1 State: anchor handle (null until first OPEN), `captured_by_us`, registry entry ID of the IOUSBHostDevice,
active configuration index, interface-owner map (bInterfaceNumber -> messenger, plus a `releasing` flag), lease set,
grace timer, state (2.4.2).
2.5.2 LEASE (connection queue, registry mutex, no device queue): unknown token or state not listed/capturing ->
NO_DEVICE; MDM check 3.2.5 -> ACCESS; connection already leases RSUSB_MAX_DEVICES -> NO_MEM; else add (connection,
device) to the lease set (idempotent), cancel the grace timer, reply 0.
2.5.3 OPEN (validated on the connection queue, executed on the device queue): token unknown or state not
listed/capturing -> NO_DEVICE (a capture runs on the device queue, so a queued OPEN executes after it); MDM check ->
ACCESS; quota -> NO_MEM; take the lease (as LEASE). Claim set = `if` plus associated interfaces, computed over the
ACTIVE configuration only (walking `ifs` of that `cfg` in order: a VIDEO/VIDEO_CONTROL interface becomes current, each
later VIDEO/VIDEO_STREAMING one is associated with it; current resets per configuration); `if` not in the active
configuration -> NOT_FOUND. A member owned by a messenger of another connection, or by a non-closing messenger of this
connection -> ACCESS. A member owned by a `releasing` messenger of this connection -> the OPEN is parked on that
messenger and re-run when its release finishes (its reply deadline still applies).
2.5.4 First OPEN of a device instance (no anchor): `libusb_open` the anchor (error -> mapped status). If
`libusb_kernel_driver_active(anchor, i) == 1` for any altsetting-0 interface `i`: write the state entry (2.7.6), set
state `capturing`, `libusb_detach_kernel_driver(anchor, i)` once (darwin captures the whole device by re-enumeration);
success sets `captured_by_us`; ACCESS -> close anchor, ACCESS; other errors logged and the claim attempted (as
in-process). After a successful detach re-resolve and store the registry entry ID (IOUSBHostDevice with
`locationID >> 24` = bus, `USB Address` = address, VID/PID equal) and update the state entry; record the active
configuration (`libusb_get_configuration`). State back to `listed`. If no interface had a driver and at least one is
VIDEO or HID class (stale capture of a crashed process), set `captured_by_us` after the first successful claim.
Deviation from in-process, by design: capture is decided once per device instance at anchor open.
2.5.5 Messenger creation: `libusb_open` a messenger handle; claim each member with `libusb_claim_interface`, BUSY
retried twice after 10 ms; on failure release what was claimed, close the handle and return the status. Success: new
`h` (monotonic per connection), owner map updated, reply.
2.5.6 CLOSE: mark the messenger closing (new ops on it -> NOT_FOUND) and its interfaces `releasing`; cancel its bulk and
interrupt transfers (sync BULK and requests); never cancel its control transfers (darwin cancels a control transfer by
`USBDeviceAbortPipeZero`, which would abort EP0 traffic of every messenger and client on the device); wait for all of
its transfers to complete (dispatch group; control transfers end within their clamped timeout; watchdog 2.7.10); then
on the device queue release its interfaces, `libusb_close` its handle, drop its requests (2.6.6), clear the owner
entries, run parked OPENs, reply. CLOSE never ends the lease and never closes the anchor.

### 2.6 Transfers, requests, shared memory, completions
2.6.1 Timeouts: `eff = (to == 0 || to > RSUSB_MAX_TIMEOUT_MS) ? RSUSB_MAX_TIMEOUT_MS : to`.
2.6.2 CONTROL/BULK: validate (3.3), copy OUT data into a daemon-owned buffer, run the HWM filter (3.5) on that copy,
fill a `libusb_transfer` (control: 8-byte setup + data; bulk/interrupt by the endpoint's raw `bmAttributes` in the
snapshot: 2 bulk, 3 interrupt, anything else INVALID_PARAM), submit. Submit error -> reply with it. Completion ->
status mapping of libusb `sync.c`: COMPLETED -> SUCCESS + `n` (+ IN data), TIMED_OUT -> TIMEOUT, STALL -> PIPE,
NO_DEVICE -> NO_DEVICE, OVERFLOW -> OVERFLOW, ERROR and CANCELLED -> IO; no data on failure. Free transfer and buffer.
2.6.3 RESET_EP: `libusb_clear_halt` on the messenger handle, on the device queue (watchdog-covered), reply its result.
2.6.4 REQ_CREATE: endpoint must be IN with raw `bmAttributes` 2 or 3 (else INVALID_PARAM); one
`mmap(NULL, round_up(len, page), PROT_READ|PROT_WRITE, MAP_ANON|MAP_SHARED, -1, 0)`, `xpc_shmem_create`, a
`libusb_transfer` with `length = len`, timeout 0, buffer = the mapping. Shared pages hold only transfer data: never
pooled or reused, no daemon metadata in them.
2.6.5 REQ_SUBMIT: BUSY if in flight (flag set before submit, cleared on submit error); NO_MEM if the in-flight byte
quota (3.6) would be exceeded; else submit and reply with libusb's result. REQ_CANCEL: `libusb_cancel_transfer`, reply
its raw result.
2.6.6 Request lifetime: refcounted by the connection table and by libusb while in flight. REQ_DESTROY, CLOSE and
connection end drop the table reference and cancel if in flight; `munmap` + `libusb_free_transfer` happen when both
references are gone. No REQ_DONE for a destroyed request.
2.6.7 REQ_DONE from the transfer callback, `{ev, r, xs, n}`. If `xs` is NO_DEVICE the device is marked gone first (2.8).
2.6.8 Back-pressure: every send to a connection (replies and events) increments its send counter; every
RSUSB_BARRIER_EVERY sends the daemon issues `xpc_connection_send_barrier`, whose block records the counter value as
acknowledged. If `sent - acknowledged > RSUSB_MAX_UNACKED_SENDS` or a barrier has been pending for more than
RSUSB_BARRIER_STALL_MS, the connection is cancelled as stalled (log, 2.9.3).

### 2.7 Lease, grace, hand-back, state, sweep, watchdog
2.7.1 A lease is (connection, device), created by LEASE or OPEN, ended only when the connection ends (closed, crashed,
cancelled) or the device is gone.
2.7.2 When a `listed` device has no lease left, arm a one-shot grace timer (`HandBackGraceSeconds`, default 5 s). A
LEASE or OPEN during the grace cancels it; the anchor and capture are reused.
2.7.3 On expiry (device queue): if still no lease and no messenger: under the registry mutex set state `handing_back`
(LEASE/OPEN now get NO_DEVICE, ENUMERATE hides it); close the anchor; if `captured_by_us`:
- if `interfaces_held_elsewhere` (IOKit `USBInterfaceOpen` without seize on each interface of the IOUSBHostDevice
  returns ExclusiveAccess; each successful open is closed at once) -> skip, log, state back to `listed`, re-arm the
  grace timer (a root in-process process is using the camera);
- else find the IOUSBHostDevice by the recorded registry entry ID (fallback: the 2.5.4 match),
  `USBDeviceOpenSeize` + `USBDeviceReEnumerate(0)` + `USBDeviceClose` (port of `tools/release/rs-macos-release.c`),
  poll drivers attached every 100 ms for up to 5 s, remove the state entry, log. OpenSeize ExclusiveAccess -> skip,
  log, `listed`, re-arm. The re-enumerated device arrives as a new instance.
Without `captured_by_us` the anchor is closed and the state returns to `listed`.
2.7.4 Leases on a gone device end without hand-back. 2.7.5 Hand-back is never triggered by CLOSE, interface release
or any client message.
2.7.6 State dir `/var/run/io.github.dolegadolegowski.realsense-usbd/`: created with `mkdir(0700)`; then `lstat` MUST show
a directory, not a symlink, owner root, mode 0700, else remove and recreate (once; then fault + no state file). File
`captured.plist` in it (written via `mkstemp` in the same dir + `rename`, mode 0600): array of
`{RegistryID, VID, PID}` for every device captured and not yet handed back. Written before detach, updated after
detach (2.5.4) and after each hand-back. Read only if a regular root-owned 0600 file <= 64 KiB.
2.7.7 Startup sweep (background queue, does not delay the listener): for each state entry whose live device has the
recorded registry ID, an allowed VID/PID (2.4.1) and no drivers attached, re-enumerate as in 2.7.3 (incl. the
held-elsewhere check). Only recorded devices are swept. /var/run is emptied at boot.
2.7.8 SIGTERM (bootout, shutdown, uninstall): cancel the listener and all connections, cancel all transfers including
control transfers, wait up to 3 s for completions, release and close every handle, hand back every `captured_by_us`
device without grace (held-elsewhere check applies), exit 0. Plist `ExitTimeOut` is 30 s.
2.7.9 Idle exit: if for `IdleExitSeconds` (default 60) there is no connection, no open handle, no grace timer and the
sweep is done, `exit(0)`. launchd relaunches on the next lookup and after crashes (KeepAlive `SuccessfulExit=false`,
which also runs the daemon once at load/boot so a crash-left capture is swept).
2.7.10 Watchdog: every backend call on a device (anchor/handle open, detach, claim, release, close, clear_halt, submit,
cancel, hand-back) and every CLOSE wait records a start time. One running longer than RSUSB_WATCHDOG_MS -> fault log,
device gone (2.8), and a forced `USBDeviceReEnumerate` through the registry ID on a separate queue (outside the device
queue), which completes the pending transfers with NO_DEVICE so normal cleanup follows. A wedged call's thread is
abandoned (it is not on a connection queue except submit/cancel, which return promptly once the device is gone).

### 2.8 Device loss (unplug, HWRST, DFU entry/exit, hand-back, watchdog)
2.8.1 On hotplug LEFT, a completion with NO_DEVICE or the watchdog (first one wins, once): state `gone`, DEVICE_GONE to
every connection with a handle or lease on the token, then let libusb complete the remaining transfers (NO_DEVICE);
every new op on its handles returns NO_DEVICE without a libusb call.
2.8.2 When its transfers have completed: release, close messenger handles and anchor, drop leases without hand-back,
remove from registry and state file, unref. Handles stay in the connection tables (NO_DEVICE) until CLOSE or
connection end.

### 2.9 Connections
2.9.1 New peer: `xpc_connection_set_peer_code_signing_requirement(peer, req)` (3.2.1; or the lightweight-requirement
fallback of 3.2.1) BEFORE `xpc_connection_resume`; a non-zero result cancels the peer. The requirement is set per
peer, not on the listener, so a rejected peer still exists and is cancelled by the NEW timeout (fast client failure).
H6 records exactly what a rejected client and the daemon observe.
2.9.2 State machine: NEW --HELLO ok--> READY; NEW --other op--> cancelled; NEW for RSUSB_NEW_TIMEOUT_MS -> cancelled;
HELLO not OK -> reply then cancel. More than RSUSB_MAX_NEW_PER_UID NEW connections of one euid -> the newest is
cancelled. Only READY connections count towards RSUSB_MAX_CLIENTS (HELLO beyond it -> AUTH_LIMIT). Malformed
messages (missing key, wrong type, unknown op) -> log + cancel. `XPC_ERROR_PEER_CODE_SIGNING_REQUIREMENT` -> log, cancel.
2.9.3 Connection end (`XPC_ERROR_CONNECTION_INVALID`): on its queue, CLOSE every messenger (2.5.6), destroy every
request (2.6.6), end its leases (2.7.1), release quotas.
2.9.4 Revocation: `{console_uid, console_gen}` is one value under a mutex. A connection stores `console_gen` at HELLO.
On a console-user change (3.2.3) the main queue bumps `console_gen` first, then cancels every non-root connection
whose euid is not the new console uid. Every op (LEASE, OPEN, CONTROL, BULK, RESET_EP, REQ_*) of a non-root connection
whose stored gen != current and whose euid != current console uid cancels the connection. On a managed-preferences
change that disallows the camera (3.2.5) every connection, root included, is cancelled.

### 2.10 Logging
os_log subsystem `io.github.dolegadolegowski.realsense-usbd`, categories `conn`, `device`, `policy`, `xfer`.
Default (persisted) level, `%{public}` for pid, uid, opcode, VID/PID and the `proc_pidpath` of the peer (best effort,
from the pid of `xpc_connection_get_pid`, diagnostics only): connection admitted/rejected with reason, lease start and
end, capture, hand-back result, device arrival/loss, revocation, every policy denial. Rate limit: one line per (pid,
reason) per 10 s, then a suppressed-count line. Debug only: per-transfer traces. Never log payload bytes or
descriptor contents.
At start (category `policy`, default level): `allowlist usbd.plist: build <n>, <k> code hashes`, one line
`allowlist usbd.d/<name>: build <n>, <k> code hashes` per admitted extra list (5.5), `allowlist usbd.d/<name>: made
for protocol <p>, its programs get AUTH_VERSION` for a list of another protocol version, then `admitting <N> code
hashes`; every skipped list or an unsafe `usbd.d` is a fault line `allowlist usbd.d/<file>: <reason> skipped` (or
`allowlist usbd.d: unsafe directory skipped`). The admitted line names the list(s) holding the peer's cdhash:
`pid <p> uid <u> admitted by <usbd.plist and/or list names | an unknown list> (<path>)`; the cdhash comes from
`peer_policy::peer_cdhash` (`SecCodeCreateWithXPCMessage` on the HELLO message, so its audit token, then
`kSecCodeInfoUnique`), only for admitted peers and only for this line.

## 3. Security

### 3.1 Threat model
Protects against: other local users (incl. a background fast-user-switch session), non-allowlisted programs,
malformed or hostile messages from allowed clients (root memory safety), the one-shot destructive flash opcodes,
bypassing MDM/Screen Time camera bans, capture of non-camera USB devices. The boundary is "console uid or root"; the
audit-session check (3.2.2) only guards against accidental use from SSH and is not a boundary (same-user SSH can start
programs in the GUI session with `open`).
Not protected (README "Security" and "Privacy"): code running as the console user can run allowlisted programs, or
copy an app and swap its ad-hoc dylibs (the cdhash covers only the main executable), so the allowlist is version
pinning plus a block on casual non-RealSense clients, not code containment; the daemon's message parser is therefore
reachable by any console-user malware. Brokered RGB/IR/depth shows no macOS camera prompt and no camera indicator, and
MDM PPPC rules cannot target it (only `allowCamera=false` is honoured). Erase/write of flash sectors (FES/FWB) stays
allowed for firmware update unless `ProtectedFlashRanges` is configured, so a standard user can make a camera need
recovery. Pre-authentication surface: libxpc deserialization (Apple) and libusb's descriptor parsing as root on
hotplug (fuzzed in H5, libusb kept pinned and updated).
Lists of other projects (rev. 3): an administrator may admit programs of other projects (`usbd.d`, 5.4). Each list
widens the set of programs that use RealSense cameras without a password, with the same caveats as the viewer's
own list: version pinning, not code containment, and same-user code can run them. Lists cannot change daemon
settings (no `DaemonCDHash`, no 5.2 keys, no effect on the HELLO `build`), cannot displace the viewer's hashes (the
own list comes first in the merge) and cannot stop the daemon from starting (invalid lists are skipped). Only root
writes `usbd.d`, and an administrator adds each list (6.7). Capacity: 16 lists and 256 hashes in total.

### 3.2 Peer admission
3.2.1 Code signing: at start the daemon builds `cdhash H"<h1>" or cdhash H"<h2>" ...` from the admitted hashes
(`AllowedCDHashes` of `usbd.plist` first, then the admitted lists of `usbd.d`, 5.5; without lists exactly the
string of rev. 2). If H6
shows that `xpc_connection_set_peer_code_signing_requirement` rejects the maximum-size (256-hash) string, the daemon
instead uses `xpc_connection_set_peer_lightweight_code_requirement` with `{"$or": {"cdhash": [...]}}` (macOS 14.4+).
Empty or invalid list -> no peer is admitted.
3.2.2 User: HELLO is OK only if `xpc_connection_get_euid(peer) == 0`, or it equals the console uid (3.2.3), the console
uid is >= 501, and the peer's audit session (`xpc_connection_get_asid` + `SessionGetInfo`) has
`sessionHasGraphicAccess` and not `sessionIsRemote`. Session not queryable -> AUTH_USER (fail closed; HW-G4).
3.2.3 Console user: `SCDynamicStoreCopyConsoleUser` at start, kept current with a notification on
`State:/Users/ConsoleUser` (`SCDynamicStoreSetDispatchQueue`, main queue), triggering 2.9.4. A console uid that is
neither 0 nor >= 501 (e.g. `_mbsetupuser`) admits no user peer.
3.2.4 Version: client `pv` != RSUSB_PROTOCOL_VERSION -> AUTH_VERSION.
3.2.5 Camera restriction. Sources (each opened `O_NOFOLLOW`, regular file, <= 1 MiB, CFPropertyList):
- `/Library/Managed Preferences/com.apple.applicationaccess.plist` key `allowCamera`;
- `/Library/Managed Preferences/<console user>/com.apple.applicationaccess.plist` key `allowCamera`;
- `/Library/Managed Preferences/<console user>/complete.plist` -> `com.apple.applicationaccess` -> `allowCamera` ->
  `value` (MCX wrapping written by Screen Time).
Deny if any present value is not exactly boolean true (a non-boolean fails closed); absent everywhere -> allowed.
Deny = AUTH_CAMERA_DISABLED at HELLO, ACCESS at LEASE/OPEN. Re-read at every HELLO, LEASE and OPEN (no caching) and
whenever a `DISPATCH_SOURCE_TYPE_VNODE` source on `/Library/Managed Preferences` or the user's subdirectory fires
(re-armed on delete/rename); a change to "denied" cancels every connection (2.9.4). The user name comes from
SCDynamicStore, never from a client; rejected if empty, `.`/`..` or containing `/`. Applies to root peers too.
3.2.6 `daemon/policy.h` (`peer_policy`): `prepare(peer) -> bool` (sets the requirement), `hello(peer) -> rsusb_auth`,
`camera_allowed() -> bool`, `console() -> {uid, gen}`, change callback. Real implementation in `policy-macos`, fake in
tests (9.0.4).

### 3.3 Input validation (every field, before any lookup or libusb call; typed getters only)
| key | rule |
|---|---|
| op | known enum value; HELLO only in NEW, others only in READY |
| pv | uint64 |
| tok | uint64, nonzero; unknown -> NO_DEVICE |
| if | <= 255 and present in some configuration of the snapshot, else NOT_FOUND; membership in the active configuration is checked on the device queue once the anchor exists (2.5.3) |
| h, r | uint64 nonzero, looked up only in this connection's tables; unknown -> NOT_FOUND |
| rt | RSUSB_RT_CLASS_IF_OUT or _IN, else ACCESS |
| rq, val, idx | rq <= 0xFF, val/idx <= 0xFFFF, else INVALID_PARAM; LOBYTE(idx) in h's claimed set, else ACCESS |
| len | CONTROL <= RSUSB_MAX_CONTROL_LEN, BULK <= RSUSB_MAX_BULK_LEN, REQ_CREATE 1..RSUSB_MAX_REQUEST_LEN, else INVALID_PARAM |
| data | present iff OUT and len > 0; xpc data length == len exactly, else INVALID_PARAM |
| to | uint64, clamped (2.6.1) |
| ep | <= 0xFF; an endpoint of altsetting 0 of an interface in h's claimed set (else NOT_FOUND); direction from the address, type from the raw snapshot `bmAttributes`, never from the client; BULK and REQ_CREATE need raw 2 or 3, REQ_CREATE needs IN (else INVALID_PARAM) |
3.3.1 Clients never send strings; nothing from a client is used as a path, format string, registry key or log format.
3.3.2 All size arithmetic in 64 bits with explicit overflow checks; every quota checked before allocation.

### 3.4 Ownership
Control requests are limited to class requests to an interface the same messenger holds (all librealsense EP0
traffic: UVC/XU/PU/CT, probe/commit on associated VS interfaces, HID reports, DFU on interface 0). Endpoints are usable
by the messenger holding their interface. One interface is held by at most one messenger across all connections.

### 3.5 HWM filter
3.5.1 Inspected (daemon's own copy of the OUT bytes): every CONTROL with rt 0x21 except to an interface whose
altsetting 0 is class 0xFE subclass 0x01 (DFU), and every BULK to an OUT endpoint (bulk or interrupt). A packet `p`
of length `len` is an HWM command if `len >= RSUSB_HWM_MIN_LEN` and either `p[2] == 0xAB && p[3] == 0xCD`, or it is a
CONTROL with `HIBYTE(val) == RSUSB_HWM_XU_SELECTOR && HIBYTE(idx) == RSUSB_HWM_XU_UNIT` (catches a packet with an
altered magic in case the firmware does not check it; HW-6 records whether it does).
3.5.2 Denied: `p[4]` in {FEF 0x0C, FSRU 0x0D, FPLOCK 0x0E} (fixed, cannot be removed) or in config `DeniedHWMOpcodes`.
Only byte 4 is compared (librealsense and the firmware use the low byte), so upper opcode bytes cannot smuggle it.
Any bRequest and any unit/selector is covered. Every extended-buffer chunk (`hw_monitor_extended_buffers`) is a full
command with a header, so chunking produces no false positives.
3.5.3 Optional `ProtectedFlashRanges` (5.2, default empty = librealsense's unsigned read-only-section update keeps
working): with `len >= 16`, deny FES whose byte range `[param1 * 0x1000, (param1 + param2) * 0x1000)` or FWB whose
byte range `[param1, param1 + param2)` overlaps a configured range (64-bit arithmetic, param2 == 0 never overlaps).
Signed DFU update and the unsigned RW-section update are unaffected.
3.5.4 Denial: ACCESS, nothing is sent to the device, `policy` log (rate-limited) with pid and opcode. DFU traffic
(interface 0 of a recovery PID, class 0xFE/0x01) is never filtered.

### 3.6 Quotas
Let `L = max(1, devices leased by the connection)`. Per connection: handles `16 L`, requests `32 L`, sync ops
(CONTROL + BULK + RESET_EP in progress) `16 L`, request shm bytes `64 MiB * L`, in-flight request bytes `32 MiB * L`
(RSUSB_QUOTA_*). Global: READY connections RSUSB_MAX_CLIENTS, NEW connections RSUSB_MAX_NEW_PER_UID per euid, shm
`min(RSUSB_MAX_SHM_TOTAL, physical memory / 8)`, in-flight request bytes RSUSB_MAX_INFLIGHT_TOTAL (bounds memory
wired by IOKit). Exceeded -> NO_MEM (LEASE, OPEN, REQ_CREATE, REQ_SUBMIT, CONTROL, BULK, RESET_EP).
Sizing: a streaming D455 uses 8 requests (VC interrupt 1, VS1/VS2/VS4 2 each, HID 1), 3+ handles and about 12 MiB in
flight, so per-device quotas leave 2-4x headroom for any number of cameras up to RSUSB_MAX_DEVICES.

### 3.7 Hardening
3.7.1 `otool -L` of `realsense-usbd` lists only `/usr/lib/` and `/System/Library/`; no `LC_RPATH`; signed ad-hoc with
the hardened runtime (`codesign -o runtime`), no entitlements, so library validation admits only system libraries
(HW-G5 confirms). `scripts/build.sh` checks the first two.
3.7.2 Config (5.3) verified root-owned and not group/world-writable at start.
3.7.3 The plist sets no `EnvironmentVariables`, no `UserName` (root), no std streams.
3.7.4 Clients: viewer and DQT SHOULD be signed with the hardened runtime and
`com.apple.security.cs.disable-library-validation` (needed for the bundled ad-hoc dylibs), which blocks
`DYLD_INSERT_LIBRARIES` and `task_for_pid` but not dylib swapping in a copied bundle; enabled after HW-3 passes with it.
Static linking of librealsense/glfw into allowlisted executables (so library validation can stay on) is deferred
(10.5).
3.7.5 MAY later: a seatbelt profile (no file writes outside the state dir, no network, no exec).

## 4. Client in librealsense (patch 0002)

### 4.1 Files and classes (`src/libusb/broker/`, compiled only `if(APPLE)`, namespace `librealsense::platform`)
| file | class / content |
|---|---|
| `rs-usb-broker-protocol.h` | copy of the protocol header |
| `broker-connection.{h,cpp}` | `usb_broker`: process singleton, connection, HELLO, calls with deadlines, session/generation, event routing, hidden-path list, reconnect; `xpc_ptr` RAII wrapper (`xpc_retain`/`xpc_release`, no ARC in .cpp) |
| `device-broker.{h,cpp}` | `usb_device_broker : usb_device, enable_shared_from_this` - snapshot, caller's info, token, generation, callback queue, dead flag |
| `messenger-broker.{h,cpp}` | `usb_messenger_broker : usb_messenger` - handle id, sync ops, request factory |
| `request-broker.{h,cpp}` | `usb_request_broker : usb_request_base` - remote id, shm mapping, per-request mutex, active flag |
Interfaces and endpoints reuse `usb_interface_libusb` / `usb_endpoint_libusb` unchanged, constructed from
`libusb_interface` / `libusb_interface_descriptor` / `libusb_endpoint_descriptor` structs filled from the wire bytes
(the classes copy the structs in their constructors). This guarantees identical `get_type()` (raw bmAttributes),
`first_endpoint`, `get_associated_interfaces`.
4.1.1 `src/libusb/CMakeLists.txt`: `if(APPLE) target_sources(${LRS_TARGET} PRIVATE <the files above>) endif()`.
4.1.2 Every xpc read uses one typed-getter helper (`get_u64(dict, key, uint64_t&)`, `get_data`, `get_array`,
`get_string`, `get_shmem`) that checks `xpc_get_type`; a missing or mistyped key makes the reply invalid (4.3.3).

### 4.2 Hook and selection
4.2.1 At the top of `usb_enumerator::query_devices_info()` and `usb_enumerator::create_usb_device()`:
`#ifdef __APPLE__ if( auto broker = usb_broker::instance() ) return broker->...; #endif`.
4.2.2 `usb_broker::instance()`: `std::call_once`; connect with `XPC_CONNECTION_MACH_SERVICE_PRIVILEGED`; HELLO (4.7.2).
Accept only `st == 0 && auth == OK && pv == RSUSB_PROTOCOL_VERSION`. Otherwise cancel the connection, LOG_INFO the
reason ("not reachable: not installed, turned off, or this build is not allowlisted" / "not the console user" /
"camera disabled by policy" / "protocol version" / "too many clients") and return `nullptr` for the rest of the
process: in-process libusb, root required as today. Decided once; never switches later. Root processes use it too.

### 4.3 Enumeration and device snapshot
4.3.1 `query_devices_info()`: `ensure_session()` (4.7.4); if the hide window (4.7.5) is open, return an empty vector;
ENUMERATE (failure or missed deadline -> empty vector); drop devices whose path is in the hidden-path list (4.7.5).
Per device, per interface dict: `mi` = index within its `cfg`; skip altsetting-0 subclass 2 and class 0xFE; emit
`{id = unique_id = path, vid, pid from dd, mi, cls = class, conn_spec = usb_spec(bcdUSB from dd), serial = ""}`, in
reply order.
4.3.2 `create_usb_device(info)`: `ensure_session()`; ENUMERATE; first device with `path == info.id` and not hidden,
else `nullptr`; LEASE(tok) - any failure -> `nullptr` (missed deadline also ends the session, 4.7.3). The device
stores the caller's `info` verbatim, its token, the session generation, and builds once: interfaces (all `ifs`,
altsetting 0), associated interfaces (device-libusb.cpp rule: walking `ifs` of the same `cfg` in order, `current`
reset per `cfg`), descriptors in contract order (device descriptor `{dd[0], dd[1], dd[0] bytes}`; per altsetting
`{d[0], d[1], d[0] bytes}` then each `extra` record split by its own bLength, stopping on bLength < 2 or overrun).
Byte counts beyond the wire length are zero-filled.
4.3.3 Every reply is validated against the header limits before use (types, lengths, counts, `n <= len`, shm size >=
len); an invalid reply is treated as a failed call. Getters never do IPC.

### 4.4 Messenger
4.4.1 `open(n)` (device): dead or stale generation -> `nullptr`; OPEN with RSUSB_DEVICE_CALL_TIMEOUT_MS; any failure ->
`nullptr` (never throws).
4.4.2 `control_transfer` / `bulk_transfer`: dead/stale -> NO_DEVICE without IPC. `bulk_transfer` first applies the
in-process type check (`get_type()` BULK or INTERRUPT, else OTHER). Lengths above the protocol limits ->
INVALID_PARAM. Deadline = clamped timeout + RSUSB_REPLY_MARGIN_MS; missed -> TIMEOUT (late reply dropped; the daemon's
transfer ends by its own timeout, no state remains). On SUCCESS copy `n` IN bytes (`n <= length`) into `buffer` and
set `transferred = n`; on failure leave `transferred` and `buffer` untouched. Status mapping as `libusb_status_to_rs`.
4.4.3 `reset_endpoint`: RESET_EP (RSUSB_DEVICE_CALL_TIMEOUT_MS), timeout argument ignored. `create_request`: local
object only, `set_shared(rv)`.
4.4.4 Destructor: stale generation -> nothing (the daemon dropped the connection's handles). Device alive: CLOSE with
RSUSB_DEVICE_CALL_TIMEOUT_MS, result ignored. Device dead in the current session: CLOSE without waiting (the handle
stays in the daemon's table and OPEN quota until CLOSE, 2.8.2; the lost device's queue may be wedged).

### 4.5 Requests, shared memory, completion dispatch
4.5.1 `set_native_buffer`/`set_native_buffer_length` only record pointer and length. `get_native_request()` returns
`this`. `get_actual_length()` returns the value stored by the last completion.
4.5.2 `submit_request`: dead/stale -> NO_DEVICE. Endpoint raw type (`get_type()`) not 2 or 3 -> INVALID_PARAM without
IPC (as request-libusb.cpp). If no remote request exists or its length differs from the native length (request
idle): REQ_DESTROY the old one, REQ_CREATE, `xpc_shmem_map` (keep `{addr, size}`; `munmap` on destroy); failure ->
mapped status. Register the route, `_active = true`, REQ_SUBMIT; error -> `_active = false`, return mapped status. A
REQ_DONE arriving before the SUBMIT reply is processed normally.
4.5.3 `cancel_request`: no remote id or not active -> SUCCESS; REQ_CANCEL; NOT_FOUND -> SUCCESS; other error -> mapped.
4.5.4 Routing: one route map per session (`std::map<uint64_t r, usb_request_broker*>`) guarded by a session
`route_mutex` held only for lookup/insert/erase and for pinning (a per-request `busy` count). The connection's event
handler looks up the device callback queue and `dispatch_async`s `{generation, r, xs, n}` there. On the callback
queue: `route_mutex`: find route in that generation's map (absent -> drop), pin, unlock; per-request mutex: copy
`min(n, shm size, native length)` bytes from shm into the native buffer, store actual length, if `xs` is NO_DEVICE
mark the device dead, `response = get_shared()`, `_active = false`, unlock; unpin; if `response`, call
`get_callback()->callback(response)` outside all locks. A whole generation's map is dropped in 4.7.3.
4.5.5 Destructor (<= ~100 ms, never waits for the daemon): if active send REQ_CANCEL without waiting; poll `_active`
10 x 10 ms; `route_mutex`: erase the route, wait while pinned (a copy in progress); per-request mutex: `munmap`; send
REQ_DESTROY (no reply). The daemon frees the transfer only after it completes (2.6.6).

### 4.6 Threads
4.6.1 Connection target queue: serial, events and errors only; never blocks and never sends with reply.
4.6.2 Replies: `xpc_connection_send_message_with_reply` on a global concurrent queue; the caller waits on a
`dispatch_semaphore` with the deadline; call state is a `shared_ptr` captured by the reply block.
4.6.3 Callbacks: one serial queue per `usb_device_broker`, QoS user-interactive. Sync calls (incl. resubmit) are allowed
from it because replies arrive on 4.6.2.
4.6.4 All messenger methods are thread-safe and concurrent; no client lock is held across an IPC wait except the
session read lock (4.7.3).

### 4.7 Session, reconnect, loss
4.7.1 A session is one successful HELLO on the current connection object, identified by a generation counter.
Device, messenger and request objects remember their generation; a mismatch means NO_DEVICE / `nullptr`.
4.7.2 HELLO: deadline RSUSB_HELLO_TIMEOUT_MS overall; `XPC_ERROR_CONNECTION_INTERRUPTED` before the reply (daemon
idle-exiting or relaunching) is retried up to 3 times within that budget; `_INVALID` is final for this attempt (a
non-allowlisted build gets it after about RSUSB_NEW_TIMEOUT_MS).
4.7.3 Session end - on `XPC_ERROR_CONNECTION_INTERRUPTED` / `_INVALID`, or when a call other than CONTROL, BULK,
ENUMERATE or HELLO misses its deadline (the client then cancels the connection itself): under the session write lock
bump the generation, mark the session down, mark every live device dead; for every routed active request deliver a
completion `{n = 0, xs = NO_DEVICE}` through 4.5.4, then drop that generation's map; open the hide window (4.7.5).
Outstanding calls fail (missed deadline or error reply -> NO_DEVICE; OPEN -> `nullptr`; REQ_SUBMIT -> NO_DEVICE with
`_active = false`). The daemon cleans up everything of the cancelled connection (2.9.3), so no late reply can leak
daemon state. Non-HELLO sends take the session read lock and check the generation.
4.7.4 `ensure_session()` (from `query_devices_info`/`create_usb_device` only): if down, recreate the connection object
when it is INVALID (at most once per second) and HELLO again; failure -> empty list / `nullptr`. Never falls back to
libusb after the first successful HELLO.
4.7.5 Hiding (so `polling_device_watcher`, 2 s period, always sees a removal; device ids usually do not change):
- session end: `query_devices_info` returns an empty vector until `RSUSB_LOSS_HIDE_MS` after the loss was detected;
- `DEVICE_GONE(tok)` or a completion with NO_DEVICE: every live `usb_device_broker` of the current generation with that
  token is marked dead (sync ops NO_DEVICE without IPC, `open()` `nullptr`) and its path is hidden from
  `query_devices_info` and `create_usb_device` until `RSUSB_LOSS_HIDE_MS` later.

### 4.8 Test hook
`usb_broker::use_endpoint_for_testing(xpc_endpoint_t)` (internal, default visibility, not in public headers) makes
`instance()` connect with `xpc_connection_create_from_endpoint`; it must be called before the first enumerator call.
`usb_broker::hide_ms_for_testing(uint32_t)` overrides RSUSB_LOSS_HIDE_MS. Used only by `rs-usbd-tests`. No environment
variable.

## 5. Configuration
5.1 `allowlist.plist` (generated by `package.sh`, shipped in each app and the Tools folder, world-readable): `Version`
(integer 1), `BuildID` (64 lowercase hex: SHA-256 of the sorted allowlist joined by `\n`), `BuildNumber` (integer,
`date -u +%Y%m%d%H%M` at packaging, monotonic), `ProtocolVersion` (integer), `AllowedCDHashes` (1..256 strings, each
`^[0-9a-f]{40}$`), `DaemonCDHash` (one of them).
5.2 `/Library/Application Support/RealSense Viewer/usbd.plist`, root:wheel 0644, directory root:wheel 0755: the 5.1
keys plus optional admin keys `HandBackGraceSeconds` (0..600, default 5), `IdleExitSeconds` (10..3600, default 60),
`DeniedHWMOpcodes` (array of 0..255), `ProtectedFlashRanges` (array of `{Start, Length}` integers, byte offsets,
Length > 0, Start + Length <= 2^32). README lists D500 `SAFETY_PRESET_WRITE` 0x95 and `CALIBRESTOREEPROM` 0xA8 as
`DeniedHWMOpcodes` candidates for D585S safety cameras and documents that the fixed denylist stops only FEF, FSRU and
FPLOCK.
5.3 At start the daemon opens it `O_NOFOLLOW`, requires a regular file owned by root, not group/world-writable,
<= 64 KiB, parent directories root-owned and not group/world-writable, all keys of the right type and range;
otherwise exit 0 with a fault log (every client then falls back). Unknown keys are ignored. Read once per process.
5.4 Lists of other projects (rev. 3): `/Library/Application Support/RealSense Viewer/usbd.d/<Name>.plist`, XML or
binary plist, <= 64 KiB, root dictionary, written only by `camera-access-allowlist.sh` (6.7), root:wheel 0644 in a
root:wheel 0755 directory:
| key | type | rule |
|---|---|---|
| `Version` | integer | exactly 1 |
| `Name` | string | equals the file name without `.plist`; the name rule below |
| `BuildID` | string | `^[0-9a-f]{64}$`: SHA-256 of the sorted (C locale), unique `AllowedCDHashes` joined by `\n` without a trailing newline (the 5.1 formula). The daemon checks the format; the list tool the value |
| `BuildNumber` | integer | 0..999999999999999999; logs and the list tool's downgrade check only |
| `ProtocolVersion` | integer | 1..2147483647. Daemon: another value than `RSUSB_PROTOCOL_VERSION` keeps the list (its programs get a clear AUTH_VERSION at HELLO), logged at info level. List tool: must equal the installed `usbd.plist` `ProtocolVersion` |
| `AllowedCDHashes` | array of strings | 1..64 entries, each `^[0-9a-f]{40}$`, all different (a duplicate makes the file invalid) |
Unknown keys are ignored by the daemon and never written by the list tool. A list sets nothing else: no
`DaemonCDHash`, no 5.2 key (unknown keys here), no effect on `BuildID`/`BuildNumber` of the HELLO reply.
Name rule (daemon and list tool): 3..100 characters and
`^[a-z0-9]([a-z0-9-]*[a-z0-9])?(\.[a-z0-9]([a-z0-9-]*[a-z0-9])?)+$` - reverse DNS in lower case with at least one
dot, so no `/`, no `..`, no leading dot (no path traversal) and no collision on a case-insensitive volume.
5.5 Loading and merging (`config.{h,cpp}`: `load_extra_lists`, `apply_extra_lists`, `lists_admitting`), right after
`usbd.plist` passed 5.3, with the same trust rules:
- Directory: absent (`ENOENT`) -> no lists, nothing logged. Otherwise `open(O_RDONLY|O_DIRECTORY|O_NOFOLLOW|O_CLOEXEC)`
  + `fstat`: a directory owned by root with `(st_mode & 022) == 0`, else one fault line and no lists. Its parents are
  those of `usbd.plist`, checked in the same start.
- Entries (`fdopendir(dup(dfd))`): names starting with `.` are skipped silently (the list tool's temporary files); a
  name not ending in `.plist` or whose stem fails the name rule gets a fault line. Candidates are sorted bytewise;
  only the first 16 (`MAX_EXTRA_LISTS`) are read, each further one gets "more than 16 lists".
- Each file: `openat(dfd, name, O_RDONLY|O_NOFOLLOW|O_NONBLOCK|O_CLOEXEC)` (a FIFO cannot block the start), `fstat`:
  `S_ISREG`, owner root, `(st_mode & 022) == 0`, `st_nlink == 1`, size <= 65536; read fully; parse per 5.4 against
  the expected name. Any failure: a fault line with the reason, the file is skipped.
- With `require_root = false` (tests) only the owner checks are skipped. An invalid list or directory never stops
  the daemon; the own list is loaded and enforced as before; an invalid `usbd.plist` still refuses the start (5.3).
- Merge (always run, also without lists): `admitted` = `AllowedCDHashes` of `usbd.plist` (file order); then each
  list in name order adds its hashes not yet admitted, unless that would exceed 256 (`MAX_ADMITTED_HASHES`, the size
  H6 qualified): then the whole list is skipped ("more than 256 code hashes together with the lists before it"), a
  list is never partly admitted. The requirement (3.2.1) is built from `admitted`.
- Read once per process like 5.3: a new or removed list takes effect at the next daemon start (the list tool
  restarts the daemon; an idle exit followed by a relaunch also picks it up).

## 6. Installer and uninstaller (bash, run as root)

6.1 Common preamble (both scripts): shebang `#!/bin/bash -p`; first lines `unset IFS CDPATH ENV BASH_ENV TMPDIR`,
`export PATH=/usr/bin:/bin:/usr/sbin:/sbin`, `umask 022`, `set -euo pipefail`. euid 0 required, except
`install-camera-access.sh --dry-run --root <dir>`, which requires euid != 0, writes the layout under `<dir>`, skips
`launchctl`, and runs the trust checks in report-only mode (for H7). `--root` without `--dry-run` is refused. Lock:
`mkdir /var/run/io.github.dolegadolegowski.realsense-usbd.install.lock` (exists -> "another install/uninstall is
running", exit 1); `trap` on EXIT removes the lock and `$STAGE`.
6.2 Trust rule for a path P: refuse if a directory component of P as given is a symlink (every later use would
re-resolve it); `realpath` P, refuse if it contains `/AppTranslocation/`; `lstat` every component of the
resolved path up to `/`: owner root or a member of group `admin`, not world-writable, group-writable only for group
`admin`/`wheel`, no ACL entry that allows write, append, add_file, add_subdirectory, delete, delete_child,
writeattr, writeextattr, writesecurity or chown. Source dirs are used by their resolved path after the check. A file additionally must be a regular file (`-f` and not `-L`), link count 1, not group/world-writable
except group admin/wheel.
6.3 `install-camera-access.sh --source <dir> [--allow-downgrade]`; `<dir>` holds `realsense-usbd` and
`allowlist.plist` (an app's `Contents/MacOS/` + `Contents/Resources/realsense-usbd/`: `--source` may be given twice,
or `RealSense Tools/camera-access/`). Steps:
1. 6.2 on the script's own resolved path (`$0`), on `camera-access-allowlist.sh` in the directory of the resolved

## 7. Launcher (`macos/launcher/main.swift`)
7.1 `geteuid() == 0` -> exec the target (unchanged).
7.2 Before `NSApplication.shared`: run the bundled `Contents/MacOS/realsense-usbd --probe` (posix_spawn, stdout pipe,
8 s watchdog). Exit 0 and the installed `usbd.plist` BuildID equal to the bundled allowlist's -> `execv(target)` as the
current user with the inherited environment; no AppleScript, no `rs-macos-release`, no `rs-macos-handback`. (The probe
only proves the bundled `realsense-usbd` is admitted; its cdhash survives builds that changed only the tools.)
7.3 Otherwise start AppKit. Facts: installed = LaunchDaemon plist exists; installed config = `usbd.plist`
(world-readable); bundled = `Contents/Resources/realsense-usbd/allowlist.plist`; disabled =
`statusForLegacyPlist == .requiresApproval`; trusted = the app bundle path passes 6.2 (done in Swift with `lstat` and
`acl_get_link_np`, incl. the `/AppTranslocation/` check), and so do the bundled `realsense-usbd`,
`install-camera-access.sh`, `camera-access-allowlist.sh` (the installer needs it, 6.3 step 1) and `allowlist.plist`.
The installed `BuildID` compared here is always the viewer's own `usbd.plist`; the lists in `usbd.d` play no part in
the launcher's decisions. The bundle path is `realpath`ed once at start and every path
(trust check, probe, install and run-once commands) is derived from it. "Install"/"Update"/"Reinstall" buttons are shown only when trusted; when not trusted
they are replaced by the text "Move RealSense Viewer to /Applications (an administrator must do this), then open it
again."
| probe / state (first match) | dialog |
|---|---|
| exit 4 | "Camera use is disabled on this Mac by its administrator." / Cancel |
| exit 6 | "Too many RealSense programs are running." / Cancel |
| exit 3 | "Only the user logged in at this Mac's screen can use the camera." / Run once as administrator / Cancel |
| not installed | Install camera access for all users / Run once as administrator / Cancel |
| installed, disabled | Open Login Items settings (`SMAppService.openSystemSettingsLoginItems()`) / Run once as administrator / Cancel |
| installed `BuildNumber` > bundled | "Camera access is newer than this app; install the app from the same DMG." / Run once as administrator / Cancel |
| installed `BuildID` != bundled, or exit 5 | Update camera access / Run once as administrator / Cancel |
| installed, same `BuildID`, exit 2 | probe again after 2 s; still 2 -> Reinstall camera access / Run once as administrator / Cancel |
7.4 Install/Update/Reinstall: AppleScript `do shell script "/usr/bin/env -i PATH=/usr/bin:/bin:/usr/sbin:/sbin
/bin/bash -p <script> --source <MacOS dir> --source <Resources/realsense-usbd dir>" with administrator privileges`,

administrator's name and password. Success -> `NSWorkspace.openApplication(at: bundleURL)` with
`createsNewApplicationInstance = true`, then terminate (the new instance probes and execs). Failure -> show stderr.
7.5 "Run once as administrator" is today's path, with its `do shell script` command also prefixed by
`/usr/bin/env -i PATH=/usr/bin:/bin:/usr/sbin:/sbin` (the script already sets HOME/USER/LOGNAME/SUDO_* itself). It
is reachable only when the probe did not return 0. It runs the (possibly user-writable) bundle as root by design.

## 11. Corrections to CONTRACT.md (this section wins)
11.1 (CONTRACT 1.2) The id (= path) usually does NOT change when a device re-enumerates on Apple Silicon (D455 alone
on bus 1: `1-1-1`); the client's hide windows (4.7.5) guarantee the watcher sees the removal.
11.2 (CONTRACT 1.2) Not invisible: the viewer queries `RS2_PRODUCT_LINE_ANY`, whose NON_INTEL part
(`platform_camera_info::pick_uvc_devices`) shows third-party UVC webcams. The root in-process path lists and captures
them; the broker never does. Intentional (the daemon must never capture foreign devices); README states it; excluded
from H3/HW-2 parity.
11.3 (CONTRACT 5.1) The HWM filter uses `len >= 5` (RSUSB_HWM_MIN_LEN) and the 3.5 scope.
11.4 (CONTRACT 1.7) On a failed transfer the broker returns no IN data; libusb in-process may leave partial IN bytes in
the buffer (sync.c copies before the status switch). librealsense discards buffers on failure.
11.5 (CONTRACT 1.6) Exclusivity: an interface held by any messenger (also of the same process) -> ACCESS, like a
second in-process handle's `USBInterfaceOpen` (ExclusiveAccess -> ACCESS).

Rev. 3 - lists of other projects:
- Other projects get their own lists in a root-only `usbd.d` (5.4) instead of entries in `usbd.plist`: the viewer's
  install/update keeps replacing its own list (one build at a time) and the launcher keeps comparing only its own
  `BuildID`; updates keep the lists, uninstall removes them (6.3, 6.5).
- Merge order: the own list first, then the lists by name; a list that would exceed 256 hashes in total is skipped
  whole (never partly admitted), so lists can neither displace the viewer's hashes nor grow the requirement past
  the size H6 qualified. The list tool refuses a list the daemon would skip (6.7 step 5); for the 16 places it counts
  every validly named candidate file, as the daemon's candidate list does.
- A list with another `ProtocolVersion` is kept by the daemon, so its programs get a clear AUTH_VERSION at HELLO
  instead of a silent code-signing reject; the list tool refuses to write one.
- Adding or removing a list restarts the daemon (`kickstart -k`) instead of a live reload: the configuration stays
  read-once (5.3), and revocation ends every session at once. Running clients reconnect (4.7.4).
- Invalid lists or an unsafe `usbd.d` are faults that never stop the daemon; an invalid `usbd.plist` still does.
- `SecCodeCreateWithXPCMessage` (audit token of the HELLO message) is used for diagnostics only (which list admitted
  a peer); admission stays with the code-signing requirement of 3.2.1.
- No change to the wire protocol, `RSUSB_PROTOCOL_VERSION` or the client patch.
